<notes>
- The self-test's success condition is inverted relative to intuition: it passes when the harness FAILS on the probe. Likewise the phase's acceptance is `bash scripts/verify-resume.sh` exiting **1**. Anyone who "fixes" that to exit 0 in this phase has deleted the deliverable.
- **Make erases the exit-code vocabulary.** GNU Make 3.81 exits 2 for any failed recipe — measured both ways in a scratch Makefile: a recipe returning 1 gives `make` exit 2, and a recipe returning 2 also gives `make` exit 2. So `make verify` is only ever assertable as "exits non-zero", which is precisely how ROADMAP criteria 1 through 4 are worded. The 1-versus-2 distinction that ROADMAP criterion 5's refuse-to-verify clause depends on is asserted by invoking the script directly (verification steps 3 and 4, and G8.3). Do not chase a Make-level workaround.
- **One override, one code path.** G0.3's `die2` fires before every content assertion, so any control that mutates the TEX would exit 2 before reaching G4. `--skip-freshness` (implemented in Plan 01) is the single documented precedence rule: it turns G0.3 into a loud SKIP and lets the run continue. G8.2 uses it, G8.3 deliberately does not, and no Makefile target may. Rejected alternative: auto-skipping G0.3 whenever `--tex` is overridden — that would silently disable G8.3, whose whole subject is an overridden `--tex` still being refused.
- ROADMAP criterion 1 requires the probe premise to be demonstrated, not assumed — hence G7.1 asserts exit 0 and zero warnings rather than just building and moving on. Measured: exit 0, zero overfull, zero underfull, 3 pages, about 1.1 seconds.
- `verify: $(PDF)` builds a missing PDF but will not rebuild a stale one, because Make is mtime-gated and both files currently carry identical mtimes after checkout. That is deliberate: refusing (exit 2) preserves the distinction between "cannot verify" and "document is wrong", and keeps the gate safe on a clean checkout and in a future CI run.
