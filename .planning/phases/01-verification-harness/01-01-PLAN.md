Harness CLI surface (scripts/verify-resume.sh):
  verify-resume.sh [--pdf PATH] [--tex PATH] [--manifest PATH] [--frozen PATH]
                   [--skip-freshness] [--selftest] [--write-baseline]
                   [--census TEXTFILE] [-h|--help]
  Env fallbacks: VERIFY_PDF, VERIFY_TEX, VERIFY_TMPDIR
  Defaults: PDF=docs/AshutoshTiwari.pdf  TEX=docs/main.tex
            MANIFEST=docs/verify/manifest.txt  FROZEN=docs/verify/baseline-frozen.txt

Mode semantics (pinned here so Plans 02/03 do not invent them):
  --skip-freshness  G0.3 emits `RESULT G0.3 SKIP` naming that the freshness proof was
                    waived by explicit request, and the run CONTINUES into G1-G6 instead
                    of die2-ing. G0.1, G0.2 and G0.4 still run. This is the single
                    documented precedence rule for the G0.3-before-everything ordering:
                    without it, any run whose --tex differs from the .fdb_latexmk record
                    exits 2 before a content assertion can report. It exists for Plan 03's
                    G8.2 geometry-drift control; no Makefile target may pass it, and a run
                    carrying it is not a verification pass. Do NOT add a second override,
                    and do NOT auto-skip G0.3 merely because --tex was overridden — Plan
                    03's G8.3 control depends on an overridden --tex still being refused.
  --census FILE     Census-only run against FILE as a raw text layer. Runs G0.1 (tool
                    probe) ONLY; skips G0.2/G0.3/G0.4 entirely because no PDF and no TEX
                    are read, and skips G1-G5, G6.5-G6.15, G7 and G8. Runs only the
                    G6.1-G6.4 glyph-class gate. FILE must exist and be readable or die2.
                    Exit: 0 when G6.1-G6.3 all pass, 1 when any of them fails, 2 when a
                    required tool or FILE is missing. Plan 03's G8.4 control depends on
                    exactly this surface.

Structured output contract (one line per assertion, stable order):
  RESULT <id> <PASS|FAIL|WARN|INFO|SKIP> <human message>
  printf format: 'RESULT %-6s %-5s %s\n'

Exit vocabulary (load-bearing — Plan 03 asserts on it):
  0 = every BLOCKER passed
  1 = at least one BLOCKER failed (the document is wrong)
  2 = the harness could not run (missing tool, missing artifact, stale PDF)
  Note: GNU Make 3.81 exits 2 for ANY failed recipe, so this 1-vs-2 distinction is
  observable only when the script is invoked directly, not through `make verify`.

Shell functions Plans 02/03 call:
  result <id> <status> <message>   # FAIL increments BLOCKERS; PASS/INFO/SKIP do not
  warn   <id> <owner> <message>    # prints WARN with "(owner: Phase N)" when <owner> is
                                   # numeric, otherwise "(owner: <owner>)" verbatim so the
                                   # sentinels `none`, `unassigned` and `any` print as-is;
                                   # never touches BLOCKERS
  info   <id> <message>
  die2   <message>                 # prints "!! <message>" and exits 2. It does NOT emit a
                                   # RESULT line — any caller that needs a machine-readable
                                   # record must emit `result <id> FAIL <msg>` immediately
                                   # BEFORE calling die2. G0.3's stale path does exactly
                                   # that, because Plan 03's G8.3 greps for RESULT G0.3 FAIL.
  manifest_get <KEY>               # single value, trailing comment and whitespace stripped
  manifest_list <KEY>              # pipe-separated value split to one item per line

Text inputs Plans 02/03 read (created by this plan's extraction step):
  $WORK/raw.txt    # pdftotext default mode, verbatim
  $WORK/gate.txt   # raw.txt with form feeds translated to newlines — the ONLY
                   # valid input for any whole-line (grep -Fx) matcher
